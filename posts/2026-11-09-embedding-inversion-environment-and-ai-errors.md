# 向量反演客户测试：环境突破与 AI 判断失误

在一次真实客户授权安全测试中，目标是找到承载敏感文档的检索系统，取得嵌入向量，并判断能否从向量中恢复短文本。测试最终得到一个经独立核验的候选值。结果背后有两条值得分开讨论的主线：环境是如何一步步进入的，以及自动化分析为何反复在关键判断上犯错。

客户名称、域名、地址、账户、口令、哈希、私钥、原始向量和可直接复用的命令均不公开。以下保留测试中的服务关系、判断依据、失败路径与验证方法；脱敏不等于把因果链删掉。

## 环境突破：先找到真正的数据面

### 入口主机上的 RAG 链路为什么是误导

测试范围包含一台 Windows 域控、一台 Windows 成员服务器和一台 Linux 主机。成员服务器开放研究门户、Qdrant 和 MongoDB，门户文字声称具备“向量检索 + 元数据”的完整 RAG 链路，活动区还显示嵌入更新记录。只看页面和端口，成员服务器很容易被当成目标系统。

数据层给出了相反证据。Qdrant 集合为空，遥测里没有与页面叙事对应的写入；MongoDB 只见系统库；门户程序中的 Qdrant、MongoDB 字样只出现在介绍文案，未发现实际后端调用。页面显示的文档计数也缺少数据层支撑。单一空集合仍可能是权限或时点问题，但遥测、程序引用和数据库内容三项相互印证，足以把这套门户从主要目标中排除。

这一阶段最重要的动作是证伪。门户可以把“系统存在”展示得很像事实，真正需要确认的却是数据写在哪里、请求是否真的到达后端、所谓活动记录能否在存储和遥测中找到对应事件。

### 双视角枚举排除了网络假设

外部测试机看到 Linux 主机主要暴露 SSH，未看到向量服务。为排除“服务仅向内网成员服务器开放”的可能，又从已获授权访问的成员服务器观察域控和 Linux 主机的可达端口。两个视角都没有发现对外监听的 RAG 服务。与此同时，DNS 中还存在指向另一网段的旧记录；该网段的连通性和端口验证未支持存在对应目标主机。

这些否定结果缩小了搜索空间，但并不证明 Linux 主机没有向量服务。服务可能只绑定回环地址。区分“扫描不到”与“不存在”，是后续路径能够收敛的前提。

### 配置残留与凭据复用打开了权限边界

测试起点只有前序阶段得到的低权限身份线索。权限验证显示：该身份可访问成员服务器，能对域目录做有限的只读查询，却不能据此在域控上交互式登录或执行命令。最初围绕门户登录和常见服务反复尝试，实际进展有限。转折点来自成员服务器的部署残留：初始化介质在表面卸载后仍可通过系统保留的卷信息读取，残留元数据包含本地管理账户的凭据。

首次验证残留凭据时，目标返回的是“密码正确但必须修改”，并非普通的登录失败。测试先在获授权的交互式登录流程中完成改密，再确认本地管理权限生效。随后检查本机凭据存储；常规远程转储没有产生可核对的结果，改用具备足够权限的本机执行通道后，才取得本机内置管理员的凭据材料。此处的内置管理员与前一步改密的本地管理账户不是同一个身份。

对取得的材料逐项做域端身份验证后，发现本机内置管理员的凭据可作为域管理员身份通过认证。至此才有证据确认权限从单机跨到域级；后续目录凭据审计又核对了同源关系。本地管理权限、凭据提取、域端验证是三个连续步骤，不能合写成“残留凭据直接拿下域”。根本问题是镜像和初始化流程未把不同管理身份的秘密隔离。

Linux 主机的入口来自另一处信任复用。先前用密码测试多个账户均未成功；本地权限提升后，重新检查成员服务器上此前不可读的用户资料，发现一把未设口令短语的 SSH 私钥。仅有私钥仍不足以登录：常见 Linux 用户名均被拒绝，重新纳入前序测试中出现的服务身份后，公钥认证才成功。成员服务器上的私钥、Linux 主机接受的公钥和对应身份共同构成跨主机路径。私钥内容、账户映射和路径细节不影响上述安全结论，因此没有公开。

### 回环服务与向量反演

进入 Linux 主机后，真实数据面才被确认：Weaviate 只监听本机回环地址，外部端口扫描自然看不到。回环绑定降低了网络暴露，但主机访问一旦成立，向量库缺少独立认证的问题就显现出来。Schema 包含论文、内部文档和密码重置策略三类对象；前两类为背景数据，敏感目标集中在最后一类。目标对象没有明文内容属性，却仍有可导出的嵌入向量。

向量导出也经历了校验过程：首次跨类别查询使用了并非每类对象都有的字段，整个查询被 Schema 校验拒绝；按各类别实际字段分别查询后，才取得目标向量，并核对对象数量、向量维度与数据格式。向量维度和环境信息帮助缩小编码模型范围，不能仅凭维度断言模型身份。

反演阶段使用约一万个已知候选词和约两万个密码重置语境模板，先筛出匹配度较高的模板，再去重并交叉比较候选。五条相互独立的模板指向同一候选，形成较强统计信号；模板相似度是排序指标，不是“结果正确的概率”。统计一致仍不等于事实成立，最终结果由独立核验确认。具体候选值和原始向量不公开。

从最初入口到结果，主要成本落在资产辨认、权限边界和认证路径上。向量反演本身在目标向量、模型范围和候选空间明确后才快速收敛。敏感文本即使不以明文属性保存，只要嵌入保留了足够语义，仍可能在受约束的候选空间内泄露。

## AI 犯错：逐项看证据，而不是只贴“幻觉”标签

自动化流程的失误并非随机口误。多个错误都发生在基础安全语义没有掌握、工具输出又未被目标侧证据校验的交界处。

1. **把认证成功当成远程执行权。** 凭据测试出现积极标记，远程桌面连接也完成了画面初始化，于是登录错误画面被误读为命令会话。实际缺少远程登录权限。端口开放、身份有效、交互式登录权和命令执行权是四个不同命题，不能用会话时长拼出执行成功。
2. **把“已执行”回显当成执行结果。** 远程管理工具打印成功消息后，目标侧没有预期文件，直接调用还返回拒绝访问。错误并不在回传设计不够复杂，而在没有先证明目标上发生了可核对的状态变化。
3. **把输出截断当成枚举完成。** 终端窗口的缓冲区吞掉了服务清单后半段，实时回显被误当作完整结果。关键枚举需要记录条数、保存完整输出并回读；屏幕上“看完了”不能证明数据采集完整。
4. **忽略多层 Shell 的语义变化。** 复杂筛选经过终端、命令解释器和 PowerShell 后，引号、变量和管道符发生变化。空结果有时来自命令本身失效，并非目标不存在。每层实际收到的参数必须核对。
5. **误用非交互认证选项。** 文件传输时启用禁止交互的 SSH 模式，却仍期望密码认证完成，导致连接失败。对协议选项的含义不清，制造了并不存在的访问障碍。
6. **把密码认证当成唯一入口。** 密码尝试持续推进，公钥认证与主机侧密钥关系检查却滞后。首次看到服务器接受的认证方式时，就应并列分析各条合法路径，而非把一条路径跑到尽头。
7. **权限升级后未重做受限枚举。** 低权限阶段读不到的目录被当作“没有文件”；提升权限后的遍历脚本又吞掉异常，形成第二次假阴性。拒绝访问、遍历失败与确实不存在必须分别记录。
8. **过早结束 DNS 线索。** 区传送被拒、反向解析超时和一次目录查询失败，只能证明对应方法失败，不能证明域内没有相关记录。需要明确“未查完”的边界，避免把排除法写成事实。
9. **用不等价样本做反演校验。** 已知文本的对照样本包含特定链接，校验运行时却没有对齐模板中的链接槽位，程序因此返回错误候选。该失败暴露的是对照设计缺陷，不能单凭这一结果否定真实目标候选；对照实验应尽量只改变待检验的明文。
10. **把写入日志当成交付成功。** 初版报告出现“已保存”的消息，回读时文件并不存在。文件存在、可打开且内容完整，才构成交付证据。测试环境中服务重建、网络抖动等时间相关事件，也不能仅凭先后顺序归因于测试动作。

这些问题的根本原因是相关知识不够扎实：Windows 登录权与凭据有效性的区别、SSH 认证选项、Shell 转义层次、日志和缓冲区语义、对照实验的变量控制，都需要准确理解。知识缺口先制造错误假设，缺少证据门槛再让错误假设驱动更多动作。单纯增加工具调用次数，只会把错误放大。

## 防守和执行如何改

- **清理部署残留。** 初始化介质、元数据和临时凭据需要在交付前验证不可再读，不能只确认盘符消失。
- **隔离每个身份的秘密。** 本地与域管理身份、不同主机的账户和 SSH 私钥应独立生成、轮换并限制使用范围。
- **保护向量数据面。** 回环监听之外仍需认证与最小权限；敏感文档进入检索系统前应做数据分级，不能把“删除明文属性”误当成向量脱敏。
- **为自动化判断设证据门槛。** 把工具回显、目标侧状态和独立验证分栏记录；权限变化后重做此前因权限受限而失败的检查；环境异常单列时间线，不凭时间相邻推断因果。

这次客户测试的核心教训并非“AI 会犯错”这一句空话。更具体的结论是：缺少领域知识时，自动化流程会把认证、授权、可达性、执行和验证混成同一个“成功”；只有补齐知识并按证据逐级确认，才可能让攻击路径和最终结论同时可信。
